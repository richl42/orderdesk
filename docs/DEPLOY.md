# Deploying Order Desk to a server

Order Desk runs as **one process** with its database and client files in one folder (`DATA_DIR`).
On a server, that folder must be on a **persistent disk**, or every deploy wipes it.
The host provides HTTPS; the app makes the login cookie HTTPS-only when `APP_ENV=production`.

What the repository already has:

| File | What it is |
|---|---|
| `render.yaml` | Render Blueprint: web service, 1 GB disk at `/var/data`, Frankfurt region, health check |
| `railway.json` | Railway start command and health check (the volume is added in the dashboard) |
| `.python-version` | Python 3.12 for both hosts |
| `app/serve.py` | The start command, `python -m app.serve`: listens on `$PORT`, trusts the host's proxy, one worker |

With `APP_ENV=production` the app **refuses to start** if `APP_PASSWORD` is under 12 characters,
`SECRET_KEY` is missing or short, `DATA_DIR` is not set or does not exist, or `AI_CACHE` is on.
The reason is printed in the deploy log.

## Before either host

1. Keep the GitHub repository **private**.
2. Get the code onto the branch you deploy from. `render.yaml` uses `main`: merge the build branch into
   `main`, or change `branch:` in `render.yaml`.
3. Choose a login password: four or five random words is good (at least 12 characters).
4. In the Anthropic console, make an API key for the server only, and set a monthly spend limit.

## Render (recommended)

A persistent disk needs a paid instance (Starter or above); the free plan has no disk.

1. Sign in at render.com and connect your GitHub account.
2. **New > Blueprint**, pick the `orderdesk` repository. Render reads `render.yaml`.
3. Fill in the values it asks for:
   - `APP_PASSWORD`: your login password
   - `ANTHROPIC_API_KEY`: the server's key
   - `AI_PRICE_INPUT_PER_MTOK`, `AI_PRICE_OUTPUT_PER_MTOK`: pounds per million tokens (optional; without them you see tokens, not pence)

   `SECRET_KEY` is generated by Render. `APP_ENV`, `DATA_DIR=/var/data` and the rest are already set.
4. **Apply**. Render builds (`pip install -r requirements.txt`), starts `python -m app.serve`, and waits
   for `/healthz` to answer.
5. Open the `https://orderdesk-….onrender.com` address it shows, log in, and on Home use
   **Set up the demo client** to check everything works.
6. Optional: your own address under **Settings > Custom Domains** (add the CNAME it shows; Render
   issues the HTTPS certificate).

Updating: `autoDeploy` is off, so pushing does nothing by itself. Push to `main`, then
**Manual Deploy > Deploy latest commit**. A service with a disk stops briefly while it restarts;
deploy when you are not mid-review. Orders being read at that moment are picked up again on start.

## Railway

1. Sign in at railway.com, **New Project > Deploy from GitHub repo**, pick `orderdesk` and the branch.
2. On the service, **Variables**, add:
   - `APP_ENV` = `production`
   - `APP_PASSWORD` = your login password
   - `SECRET_KEY` = a long random string (`python3 -c "import secrets; print(secrets.token_hex(32))"`)
   - `ANTHROPIC_API_KEY`, and optionally the two AI prices
   - `DATA_DIR` = `/data`
3. Add a volume to the service (right-click the service, **Attach volume**), mount path `/data`.
4. **Settings > Region**: pick an EU region for UK client data.
5. **Settings > Networking > Generate Domain** for an `https://….up.railway.app` address.
6. Redeploy, open the address, log in, set up the demo client.

Keep it to **one replica**: the database is one SQLite file and orders are read inside the process.

## After deploying

- **Back up**: the Home screen's **Download a backup** saves a zip to your laptop (keep FileVault on).
  A copy also stays in `<DATA_DIR>/backups` on the server, which is on the same disk, so it is not a
  backup against losing the disk. Download one at least weekly during a trial.
- **Errors**: details go to `<DATA_DIR>/logs/errors.log` and the host's log viewer.
- **Rotating the password or key**: change `APP_PASSWORD` or `SECRET_KEY` in the dashboard and redeploy.
  Changing `SECRET_KEY` logs everyone out.
- There is no restore button yet: a backup zip is the `DATA_DIR` folder as it was, to be copied back
  onto a disk by hand.
